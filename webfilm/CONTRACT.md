# 网页代码作品的公平约定

发布当天给双方同一份本约定、创作要求和工具，分别生成第一版；用 render 渲染、review 审阅，再把各自的审阅结果交回原模型修改一次，保留第一版和修改版。双方使用同一机器、Chrome、画幅、时长和修改机会。以下约定是这条创作流程的共同接口。

1. 默认交付为 3840×2160、60fps，也可明确指定 1920×1080。默认作品时长为 20 秒，工具默认上限为 120 秒；实现可以由调用者明确调整上限，比较双方使用同一值。
2. 作品是一个可以整体搬走的目录，含 `work.json` 和本地入口网页。Canvas、SVG、WebGL、HTML/CSS 都可以用。所有字体与素材来自系统或该目录，运行时不联网。
3. 不使用预录音频、预录视频或视频生成模型。旋律、音效和画面由代码生成。文件检查与断网运行能检查部分违规；模型是否调用过视频生成模型、是否隐瞒预录来源仍需作者声明和人工审核，程序不能自动证明。
4. 捕获前设置 `window.__WEBFILM_CAPTURE__ = true`。页面提供 `window.webfilm = {duration, render(t), audio(ctx)}`。`render(t)` 可同步或异步，必须按传入的绝对秒数直接决定画面；不依赖上一帧、系统时间、实时随机数或 rAF 次数。捕获模式不自行启动 rAF。
5. 有声音时，`audio(ctx)` 使用传入的 AudioContext 或 OfflineAudioContext，一次性从绝对 0 秒安排全部音符与音效，返回同步结果或 Promise。离线交付为 48000Hz、双声道；不依赖捕获工具提供的专用音频 API。无声音的作品在配置中写 `"audio": "none"`。
6. 普通 Chrome 打开原网页即可播放；实时声音由用户点击解锁。可选 `runtime.js` 提供现场播放与点击按钮，作品接口本身不依赖播放器。
7. 互动作品提供可选 `actions.json`，按时间执行 move、click、scroll、hover、wait。点击和悬停使用稳定选择器，便于 4K/1080 比较；坐标单位为 CSS 像素。滚动可包含 `duration`，wait 保持现场状态。实际用户动作是互动内容的一部分，双方使用同一动作脚本。
8. 对相同目录、相同动作、相同时间点，工具可以在固定同机 Chrome 上比较重复捕获的像素。字体、浏览器、驱动和机器不同可能改变结果，不承诺跨机器字节一致。

作品配置示例：

```json
{"schema":1,"title":"纸上远行","entry":"index.html","duration":20,"seed":829,"audio":"generated"}
```

`site.json` 将同一份 `prompt` 与各作品的版本绑定，版本可以映射到不同作品目录。内置样片是 AI 补充的渲染验收材料；其中“彩排 A / 彩排 B”是两位虚构作者，使用同一份原创代码，未代表任何模型之间的真实比赛，也不是给参赛模型的模板。

discover/capture 可捕获已有普通网页，自行导出的 MP4 也可进入后期与审阅；这些是附加能力，其可验证范围按实际捕获方式记录。
